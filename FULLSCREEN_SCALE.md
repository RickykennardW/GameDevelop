# Celestial fullscreen world scaling

Implemented in `layouts/game-scene.json`, Game Scene event group 0, from
`tools/responsive-map-runtime.js` and `tools/island-map-runtime.js`.

## Diagnosis and implementation

Previously the actual viewport drove route generation. Increasing display resolution
added road tiles and expanded the world; camera zoom was also capped at 1. At 2560x1440
there were 184 tiles, versus 113 at 1280x800. Path thickness barely increased from Full HD.

The world now uses the previous 1280x800 route: 113 tiles, left 64, right 1344,
rows 192/384/576/768/960, 64-unit road width. It is built once per scene and never
regenerated by window resizing, even before the first purchase. Five zig-zag rows and
the existing buildable gaps are retained. MonsterPathPoints still come from actual
Monster_Path centers through the unchanged native route initialization.

World camera zoom is uncapped and fits the actual complete perimeter extent plus
12 world units of clearance. The normal HUD overlays the upper decorative margin,
recovering the previously reserved full-width HUD strip; narrow portrait windows
still reserve the taller HUD band. HUD input exclusion stays unchanged.

Terrain, road, all four towers and Archer states, enemies, projectiles, Spawn/Base,
obstacles, foliage, cliffs, range, footprints and blocked circles share this uniform
world camera transform. Their individual render scales, logical sizes, authoritative
centers, stats, collision radii, movement speeds and ranges have not been altered.
UI/shop/selected panel retain their independent pixel-based layout. Camera framing
never includes movable units or a placement cursor.

MapEndpointLabel is completely removed: definition, two initial instances, object
folder entry, responsive text/position code and island positioning code. SpawnMarker
and BaseMarker structures remain. No hidden endpoint labels remain in the scene.

## Measured screen sizes

| Viewport | Zoom before / after | Path before / after | Basic visual width before / after | Archer before / after |
|---|---|---|---|---|
| 1280x800 | .604 / .619 | 38.7 / 39.6 px | 48.3 / 49.5 px | 58.0 / 59.4 px |
| 1920x1080 | .847 / .884 | 54.2 / 56.6 px | 67.8 / 70.7 px | 81.3 / 84.8 px |
| 2560x1440 | .870 / 1.189 | 55.7 / 76.1 px | 69.6 / 95.2 px | 83.5 / 114.2 px |

The improvement is approximately 37% at QHD and 4% at Full HD. Keeping every cliff
and all five route rows on screen constrains the Full HD gain; this implementation
does not claim a dramatic Full HD enlargement. No new raster art or tile stretch
was introduced. Screenshot inspection confirms the complete perimeter, clear road,
visible endpoints without labels, and unchanged shop styling.

Tests use the local exported GDevelop runtime in headless Chrome. Fullscreen API
was entered; Full HD/QHD dimensions are controlled browser viewport emulation,
not a manual observation on a physical monitor. The attached text did not include
new Bloons comparison screenshots, so no pixel-exact comparison is claimed.
