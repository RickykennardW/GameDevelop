# Pemeliharaan Celestial Void

## Sumber aktif

Project utama adalah `Tower Defense.json`; scene terpisah berada di `layouts/game-scene.json`. Seluruh property, ukuran, instance, camera, object folder, gameplay variable dan event berada pada kedua file ini. Extension Health berada di `eventsFunctionsExtensions/health.json`.

`tools/source-mapping.json` memetakan 27 source JavaScript ke event scene. `python tools/embed-free-placement.py` melakukan embedding langsung, tanpa membuat salinan. Jangan mengembalikan script migrasi lama atau file konfigurasi hasil eksperimen yang sudah dihapus. Semua perubahan harus mengikuti **NO BACKUP** pada `AGENTS.md`.

## Sistem yang dipertahankan

- Satu Star Cannon resmi, harga 300 Gold, desain Nova Spike, 27 kombinasi upgrade valid dari dua path sampai Lv5. Base tetap diam, chassis dan core mengikuti pivot bersama, barrel recoil independen. Path 1 memakai Nova setiap tembakan keempat, Armor Fracture dan Lance lurus maksimal 3 target dengan ledakan per hit; Path 2 memakai muzzle bergantian, Rhythm dan Overdrive. Targeting, sell dan footprint tetap pada sistem existing.
- Prototype Pure Fusion **Starburst Cannon** tersedia dari pasangan **5-2 + 2-5**, melalui tombol Fusion di Selected Panel. Pilih pasangan, lalu tempatkan ghost dalam radius 96 dari salah satu sumber; Cancel/Esc mempertahankan kedua sumber. Konfirmasi valid baru mengonsumsi sumber. Mode berjalan 0,5x, lalu memulihkan speed sebelumnya. `StarburstConfig` mengatur biaya test 0, damage90, interval0.4s, range227, splash64/20%, dan artwork. Varian `TowerType=StarburstCannon` memakai object `StarCannonTower` existing; shop tetap satu entry. Saat placement semua footprint terlihat; Index memiliki tab Fusion tersendiri dan discovery Fusion permanen sesudah konfirmasi sukses. Lihat `STARBURST_FUSION_REPORT.md` dan `FUSION_FIXES_REPORT.md`.
- Nova Wisp, Void Hound, Void Guard, Void Sentinel, Void Brute dan elite Void Golem menggunakan object Enemy bersama. Animasi arah/state, armor, HP, movement, death dan HP bars tetap tersedia.
- Golem memakai stationary cast dan Void Fortification: konfigurasi authoritative ada pada `VoidGolemConfig`, bukan file metadata eksperimen lama.
- Map Celestial Void, waypoints, Spawn/Base, obstacle blockers/removal, Tower Shop, Selected Upgrade Panel, Index, HUD dan camera tetap.
- 45 waves memakai `WaveBudgetConfig`, dengan milestone dan seeded enemy composition existing. Cleanup tidak mengubah harga, damage, stats, rewards, pacing, 1x/2x atau Manual/Auto.

## Placement economy dan Celestial Sonar

Shop selection tidak lagi mensyaratkan Gold. Native event selection dan input card hanya memulai/toggle builder. Preview memanggil validator shared dengan `{ignoreGold:true}` sehingga footprint/range tetap memakai collision asli dan warna menunjukkan lokasi. `p.preview.affordable` mengikuti Money aktual. Pemanggilan `p.validate` tanpa opsi tetap memeriksa Gold, termasuk Fusion. Klik pembelian normal memeriksa lokasi/UI dahulu, lalu Money terhadap cost catalog terbaru; hanya sukses yang membuat tower, memotong Gold dan menghentikan builder. Upgrade/sell/reward/harga tidak diubah.

`PlacementFeedbackConfig` menyimpan durasi 1.2 detik, cooldown 0.65 detik dan sound PurchaseDenied. `p.rejectGold`/`p.paintGold` dalam `free-placement-runtime.js` menampilkan satu notice reusable tepat di bawah Gold HUD (anchor MoneyText/HUDPanel), dengan fade ringan dan flash coral, tanpa menangkap input. Tidak ada error label dalam Tower Shop. Ghost/range tetap aktif setelah penolakan. Deficit dihitung dari Money terbaru; setelah uang cukup atau Cancel, pesan disembunyikan. Error Gold hanya dipanggil oleh klik purchase, sedangkan audio observer tetap memberi feedback collision berdasarkan validasi spatial dan mengabaikan klik shop/UI.

`tools/celestial-sonar-runtime.js` pada event akhir scene `[18].events[0]` hanya membaca enemy/route setelah movement/combat/Finish. Remaining distance memakai posisi ke waypoint berikutnya ditambah panjang seluruh segmen berikutnya. ETA real = `(remaining / MoveSpeed + remaining elite cast) / timeScale`; zero-speed/dead/finished diabaikan. Tidak memakai jarak lurus ke Base sebagai fallback yang dapat salah lintas lane, dan tidak menulis Lives, movement atau wave.

`CelestialSonarConfig` menyimpan threshold Warning 6 detik, Critical 2.5 detik, WarningRepeatSeconds 6 detik, CriticalRepeatSeconds 3 detik, hysteresis/debounce 0.25 detik dan cooldown global 1 detik, periode pulse 2/1.2 detik, Enabled, ReducedMotion dan ID sound. Satu manager mengambil ancaman paling mendesak; banyak monster tidak menambah suara per enemy. Normal membersihkan indikator, menghentikan voice sonar dan mereset jadwal repeat. Minimum gap tetap dipertahankan ketika ancaman muncul kembali. Satu voice dimiliki manager; escalation mengganti Warning dengan aman, downgrade menunggu interval Warning tanpa alarm tambahan. Jam pengulangan unscaled, cue tanpa pitch scaling, sehingga 1x/2x/Fusion 0.5x tetap nyaman. Pause native membekukan update. Browser `prefers-reduced-motion` atau config ReducedMotion menggunakan pola stabil.

Finish mendapat satu radar ring amber atau dua ring coral dengan notch berbeda; Lives mendapat outline serta `!`/`!!`. Graphics berada di bawah HP bars, noninteraktif dan dilepas saat scene unload. Tiga final OGG original adalah `assets/audio/ui/purchase_denied.ogg`, `assets/audio/gameplay/sonar_warning.ogg`, `assets/audio/gameplay/sonar_critical.ogg`. Semuanya melalui AudioConfig SFX, sehingga Master/SFX/MuteSFX mengontrolnya; BGM/volume preferences existing tetap.

Build khusus: `python tools/compose-sonar-audio.py`, `python tools/register-sonar-feedback.py`, `python tools/embed-free-placement.py`. Composer hanya mengubah tiga cue tersebut dan entrinya pada manifest; registration idempotent mempertahankan tuning config yang sudah ada. Jangan menjalankan rebuild soundtrack penuh untuk perubahan threshold. Rincian file, pengujian native dan batasan: `ECONOMY_SONAR_REPORT.md`; suite `tools/economy-placement-qa.js` dan `tools/celestial-sonar-qa.js`.

## Monster discovery dan notifikasi

`tools/monster-discovery-runtime.js` diinisialisasi sesudah responsive shop/map dan sebelum Index/spawn. Satu callback `onWaveSpawn(enemy,type)` di akhir inisialisasi enemy pada `nova-spawn-runtime.js` adalah satu-satunya trigger unlock. Jangan memindahkannya ke object creation umum atau renderer Index.

Versi beta memakai `game.__celestialMonsterDiscoverySession` di memori RuntimeGame berdasarkan ID `EnemyTypes` yang stabil (`Basic` adalah Nova Wisp). Launch aplikasi baru membuat sesi kosong; perpindahan/reload scene biasa mempertahankan discovery serta notifikasi aktif/queue. Key discovery lama `celestialVoidMonsterDiscovery.v1` diabaikan dan hanya key tersebut dihapus sekali saat sesi baru. Settings/audio tidak dihapus. Tombol Restart pada menu Game Over kini mempertahankan discovery sesi ini sesuai instruksi fitur terbaru; jangan memanggil `resetForNewGame()` dari Restart. API reset masih tersedia untuk pengujian terisolasi atau fitur reset yang diizinkan secara terpisah. Registry otomatis mengikuti archetype aktif yang memiliki animation portrait di IndexMonsterImage, dalam urutan portrait existing. Untuk monster baru, daftarkan archetype dan portrait asli; tidak perlu mengubah daftar ID dalam notifikasi.

Index memakai satu sprite artwork per thumbnail/detail, tanpa salinan shadow/outline. Object native `IndexMonsterImage` menjadi handle UI berukuran sesuai frame dengan opacity0; adapter `monster-discovery-runtime.js` memiliki satu sprite PIXI dan mask per handle melalui `indexPortraits`. Tint hitam penuh diterapkan ke texture asli dengan alpha tetap; state diambil dari discovery encounter yang sama dengan teks. Renderer Index lama Hound/Golem melewati handle yang ditandai `__archivePortraitOwned`. Original texture tidak diedit. `MonsterPortraitConfig` memilih frame idle existing per jenis. Hound memakai cell `[0,0,384,255]` dan Golem `[0,0,256,307]`; jenis lain memakai PNG individual langsung. Texture satu frame dan fit berdasarkan visual alpha bounds yang sama digunakan oleh seluruh portrait Index/notifikasi; crop GPU hanya dimiliki UI dan dilepas ketika scene unload. Hanya nama/stat/role monster yang terkunci disamarkan; Tower Index tetap penuh. Dirty key pada Index meliputi status discovery sehingga unlock langsung terlihat tanpa redraw setiap frame.

Layer `DiscoveryUI` memakai graphics/text/sprite PIXI yang reusable dan tidak interaktif. Toast 272x60 di pojok kanan atas gameplay (12px sebelum batas sidebar, y mengikuti HUD) memakai animasi 3.2 detik: enter 0.2, hold 2.7, exit 0.3, serta reveal portrait asli 38-40px. Geometry menghindari HUD/sidebar/Selected Tower Panel; queue maksimal satu entry per jenis. Cue `DiscoveryUnlock` memakai chime WaveComplete existing pada volume UI yang lebih rendah; BGM tetap berjalan. Source ada pada mapping runtime ke-24.

Discovery harus kosong lagi, preferensi audio dan key lain harus tetap. Gunakan profile test terisolasi, bukan storage pengguna.

## Starfall Bastion MainMenu

Entry scene project adalah `MainMenu` (`firstLayout` dan urutan pertama pada layouts). Start membuka `Levels`, kemudian pemain memilih misi dan menekan Launch Mission untuk masuk ke `Game Scene`. Start tidak melewati pemilihan misi. Preview khusus Game Scene di editor tetap memakai sandbox existing (Gold50000, Lives10,45waves); preview MainMenu menunjukkan alur campaign. Project display name adalah Starfall Bastion.

Menu memakai delapan object native, layer dasar/MenuUI dan satu event dari `tools/main-menu-runtime.js`. MenuConfig menyimpan StartScene=Levels, GameplayScene=Game Scene (referensi konfigurasi audio), HoverScale1.06 dan TransitionSeconds0.28. Background original, judul vector dan empat state bingkai tombol berada di `assets/ui/main_menu/`. Label tombol tetap Text Object editable. Pembuat vector/scene: `tools/build-main-menu.py`; setelah rebuild struktur lobby, jalankan `tools/build-campaign.py` untuk memasang integrasi campaign, kemudian `tools/embed-free-placement.py`. Prompt background ada di `tools/main-menu-art-prompt.md`.

Hover Start/Exit dan Restart/Main Menu hanya membesarkan bingkai, bukan label. Label memakai scale dasar viewport, wrapping width `320 * baseScale`, dan X `buttonCenterX - label.getWidth()/2`. Native wrapped Text GDevelop memusatkan renderer pada X ditambah setengah wrapping width tanpa mengalikan width dengan scale object. Jangan mengurangi setengah lebar bingkai yang sudah terkena hover scale dari posisi label: itu menyebabkan drift kiri9.6px pada hover1.06 di desain1280x720. Pengukuran glyph native per frame dan hasil resize ada di `HOVER_ALIGNMENT_REPORT.md`; suite `tools/menu-button-alignment-qa.js`.

Sacred Void Temple dan UIClick memakai AudioConfig existing dan preferensi volume/mute yang tersimpan. Browser membutuhkan gesture pengguna. Handoff audio ke gameplay dilakukan sekali tanpa mengubah mixer. Exit menggunakan aksi stopGame GDevelop; Chrome mempertahankan tab dan menampilkan pesan untuk menutup tab sendiri. Penutupan desktop build perlu diuji pada export desktop.

Validasi: `node tools/validate-clean-project.cjs --scene=MainMenu`, `python tools/run-clean-validation.py --prepare`, lalu `python tools/balance-browser.py tools/main-menu-qa.js validation/main-menu-native-tests.json --menu --gesture --viewport=1280x720`. Opsi `--mode=resize --resize-sequence=1280x720,640x400,480x300,1280x720` menguji resize satu sesi. `--mode=regression --then=tools/starburst-fusion-qa.js` menguji gameplay sesudah Start. Rincian hasil dan keterbatasan ada di `STARFALL_MAIN_MENU_REPORT.md`.

## Cinematic Game Over

`Game Scene` memakai loss existing `Lives <= 0`, terpisah dari kemenangan yang juga memakai `GameOver`. `tools/game-over-runtime.js` pada event `[19].events[0]` memiliki satu controller `scene.__gameOverUI`, satu overlay PIXI noninteraktif pada layer paling atas `GameOverUI`, serta tombol/label native yang memakai bingkai lobby. `DefeatActive`, `DefeatPhase`, dan `GameOverUIConfig` mengatur cinematic. Campaign menambahkan pasangan `DefeatLevels`/`DefeatLevelsLabel`, ditampilkan hanya pada run campaign; Restart/Main Menu tetap tersedia. Setelah rebuild `tools/build-game-over.py`, jalankan `tools/build-campaign.py`, lalu embedding normal.

Urutan waktu nyata: crimson menuju opacity60% selama1.8s, judul fade0.45s, instruksi0.2s, lalu menunggu klik/tap baru. Input selama reveal atau hold dari klik kalah diabaikan. Klik baru mengubah warna overlay yang sama menjadi near-black70% selama0.55s; tombol fade0.25s. Hover memakai helper dan HoverScale1.06 milik lobby, selalu dari ukuran referensi. Geometri mengikuti viewport existing, mempertahankan aspect ratio dan layout valid terakhir saat ukuran nol/nonfinite.

Guard native `DefeatActive=False` melindungi kelompok Index/selection/combat/wave banner dan event select/preview/purchase. Semua child event asli tetap utuh. Layer world dibekukan dengan timeScale0; clock scene/UI/audio tetap berjalan. Fusion dibatalkan tanpa mengonsumsi sumber, ghost dihentikan, input gameplay dikunci, discovery presentation ditahan tanpa menghapus antrean. Renderer map tetap aktif agar scale visual existing tidak kembali ke ukuran object asli.

Restart mengganti scene gameplay melalui aksi native tanpa aktor/projectile/tower lama. Pada campaign, misi aktif dan konfigurasi Gold/Lives/wave yang sama dimuat kembali; pada preview langsung Game Scene, inisialisasi existing Gold50000/Lives10/Wave0 tetap berlaku. Monster discovery sesi, Fusion save, dan audio preferences tetap. Main Menu menuju `MainMenu`; tombol Levels mengembalikan chapter/misi aktif. Audio GameOver dipicu sekali oleh observer existing; UIClick dan mute/volume tetap memakai mixer existing. Handoff gesture audio diberikan saat scene unload, lalu dikonsumsi oleh pemilik audio scene baru.

Validasi: `python tools/validate-game-over.py`; native fixture `tools/game-over-qa.js`, `tools/game-over-realtime-qa.js`, dan `tools/game-over-resize-qa.js` melalui driver existing. Rincian file, event, hasil aktual, dan keterbatasan: `CINEMATIC_GAME_OVER_REPORT.md`. Tidak membuat backup. Validator kebersihan penuh masih menolak editor autosave lama `Tower Defense.json.autosave`; file itu bukan hasil fitur ini dan tidak diubah.

## Galactic Campaign, tutorial dan progression

Campaign memakai tiga scene terhubung: `MainMenu` → `Levels` → `Game Scene`. Semua25misi memakai map, path, collision, tower, harga upgrade dan resep Fusion existing. Lima background SVG original di `assets/ui/campaign/` hanya untuk Levels; bukan penggantian map combat. `CampaignBackdrop` mempunyai lima animasi dan dua instance runtime untuk crossfade. Chapter memiliki lima hex pad; status locked/available/selected/completed/boss berasal dari save, bukan kondisi dekoratif.

Sumber konfigurasi tunggal: `tools/campaign-config.json` (5chapter,25misi,204wave eksplisit). Setiap misi mengatur StartingGold, StartingLives, intermission, komposisi/jumlah, interval spawn, HealthScale dan SpeedScale; boss terakhir mengatur HP/armor/speed/reward/skill/reserves. Semua nilai dapat dituning di config tanpa menyalin scene. Jalankan `python tools/build-campaign.py`, `python tools/embed-free-placement.py`, `python tools/campaign-reference.py`, lalu `python tools/validate-campaign.py`. Builder membaca config yang sudah ada agar tuning tidak ditimpa. Tabel lengkap ada di `CAMPAIGN_LEVEL_REFERENCE.md`.

`tools/campaign-service.js` dipasang pada Levels.events[0]; `tools/levels-runtime.js` pada events[1]. `game.__campaign` memegang config, pilihan misi dan save. Key localStorage `starfallBastionCampaign.v1` menyimpan Version, Completed, SelectTutorialDone dan GameTutorialDone, tanpa menulis key audio/Fusion/discovery. Frontier/chapter unlock diturunkan dari prefix completion yang valid. Hanya kemenangan run aktif yang sudah menyelesaikan semua wave, menghabiskan antrean dan mempertahankan Lives>0 dapat disimpan. Boss wajib benar-benar mati; boss lolos menyebabkan defeat. Replay tidak menghapus progress; skip tutorial tidak memberi unlock.

Gameplay initializer `tools/campaign-game-runtime.js` berada pada events[0].events[5]; `tools/campaign-game-after.js` pada events[20].events[0] setelah event combat/reward existing. `scene.__campaignRun` mempunyai state tutorial, wave yang benar-benar dimulai, kills, boss dan hasil. Hook kecil wavePlan/spawned/defeated memakai wave manager, Health dan pembayaran reward existing. Tanpa active campaign, hook tidak mengubah sandbox. Boss adalah lima konfigurasi Void Golem existing dengan portrait/animasi/casting/buff yang sama, ditambah shield/surge/reserve sesuai chapter; UID menjaga referensi boss saat object pool dipakai ulang.

Variable scene baru: CampaignLevelId (ID run), CampaignTutorialActive (coach aktif), CampaignModal (blok input world pada instruksi modal), CampaignUIConsumesClick (klik coach), CampaignCombatPaused (gate native combat dan world time scale). UI ada pada CampaignUI tepat di bawah GameOverUI. UI/tutorial tetap bergerak saat combat ditahan. Tutorial tahap placement menunggu transaksi nyata; first wave menunggu penempatan dan acknowledgment; first kill/reward menggunakan handler asli. Upgrade menggunakan panel nyata dan Continue selalu tersedia bila Gold kurang. Tutorial lengkap disimpan sekali; Index/audio dapat dibuka tanpa mengulang atau kehilangan tahap. Overlay tidak membuat pembelian ketika klik ditahan/ditarik keluar dari panel.

Levels memakai resolusi/viewport manager yang sama prinsipnya dengan UI existing, mempertahankan ukuran valid terakhir ketika hidden/zero/nonfinite. Font mempertimbangkan ukuran fisik; hover hanya mengubah frame. Container, text dan background dipakai ulang; listener dan texture text milik campaign dibersihkan saat unload, texture sprite bersama dipertahankan. Sacred Void Temple, milestone alerts dan mixer existing dipakai ulang, tanpa audio asset baru.

Validasi: compile `node tools/validate-clean-project.cjs --scene=Levels`, lalu `python tools/run-clean-validation.py --prepare`. Gunakan `tools/campaign-qa.js` (`full`, `tutorial`, `playtest`), `tools/campaign-boss-qa.js`, `tools/campaign-fusion-qa.js`, `tools/campaign-resize-qa.js` melalui `tools/balance-browser.py --levels`. `--campaign-reload-check` memeriksa reload save asli. Untuk regresi sandbox `test-clean-project` dan `test-gold-budget`, compile ulang tanpa `--scene` sebelum prepare karena harness memuat Game Scene secara langsung. Rincian metode, hasil dan keterbatasan ada di `CAMPAIGN_REPORT.md`.
